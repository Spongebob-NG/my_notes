**结论先行：在标准 BFS（权值为 1 的最短路）中，必须在节点入队（`push`）的那一瞬间立刻标记已访问。**

如果等出队（`pop`）时才标记，你的队列会因为存入大量重复节点而瞬间爆炸（MLE 或 TLE）。

------

### 1. 为什么要“入队即标记”？

我们可以用 **“抢占领土”** 的逻辑来理解：

- **入队（Push）的本质**：是由于某种原因（比如它是邻居），这个点被“预定”了。
- **出队（Pop）的本质**：是轮到这个点作为中心向外扩张了。

如果你在入队时不标记，那么在这一层的多个分身同时扫描到同一个邻居时，他们都会发现这个邻居是“未访问”的。

> **后果：** > 假设 A 和 B 都能走到 C。
>
> 1. A 扫描到 C，发现 C 没被访问，把 C 塞进队列。
> 2. **（重点）** 此时 C 还在队列里排队，没轮到它出队，所以它还没被标记。
> 3. B 也扫描到 C，发现 C 还是没被访问，又把 C 塞进队列。
> 4. 结果队列里出现了两个一模一样的 C。

对于 $N \times M$ 的网格，如果不及时标记，这种重复入队会呈指数级增长。

------

### 2. 标准 BFS 的三步走死律

为了保证不出错，你在写任何 BFS 时，请刻意练习这个**“标记闭环”**：

1. **起点初始化**：起点入队，**同时**起点标记 `vis = 1`。
2. **判断合法性**：在 `for` 循环遍历邻居时，先判断 `if (!vis[next])`。
3. **入队标记**：一旦决定 `q.push(next)`，**下一行紧接着**写 `vis[next] = 1`。

------

### 3. 唯一的例外：什么时候可以在出队时标记？

虽然在蓝桥杯的普通 BFS 题目中几乎用不到，但为了让你知识体系完整，你需要知道只有一种情况是在出队（或处理时）标记：**Dijkstra 算法（带权最短路）**。

- **原因**：在带权图中，你第一次见到某个点时，走过的路程不一定是最短的。你可能之后会发现一条更短的路到达同一个点。
- **做法**：所以你需要反复更新这个点的距离，只有当它从**优先队列（Priority Queue）**中弹出时，才说明此时拿到的距离是真正的最短距离，这时才标记“确定了”。

**但注意：** 你现在做的迷宫、胖子走路、马的遍历，每一步的代价都是 1，全都属于**标准 BFS**，请务必死守“入队即标记”的原则。

------

### 4. 特殊情况：你刚才那道“胖子题”

在那道题里，你发现“原地等待”时我没有让你标记 `f[xi][yi]`。为什么？

- 因为“原地等待”并没有产生**新的坐标**。
- `f` 数组（或 `vis` 数组）的本质是 **“坐标去重”**。
- 在原地等待时，你只是在消耗时间，并没有抢占新的领土。所以原地等待的状态直接入队即可，不需要也不应该去修改坐标的 `vis` 状态。
