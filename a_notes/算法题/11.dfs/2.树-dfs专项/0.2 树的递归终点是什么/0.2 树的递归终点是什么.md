二叉树的递归终点**既可以是空节点，也可以是叶子节点，完全取决于你要求什么。**

给你一个最直接的 **“终点法则”**：

### 1. 什么时候用 `if (!root)` （空节点作为终点）？

**适用场景：90% 的普通二叉树问题。**（比如：求深度、翻转二叉树、求节点总数、普通遍历）。

- **物理意义**：你一脚踩空了，掉到了树的外面（虚无）。
- **潜台词**：“我这里啥也没有，没法干活，我直接返回一个毫无存在感的值（0、空指针、false）。”
- **为什么选它**：因为它能**完美兼容**所有情况，包括处理只有单边孩子的节点，甚至连传进来的整棵树都是空树的情况都能兜底。

C++

```
// 例子：求二叉树节点个数
int countNodes(TreeNode* root) {
    if (!root) return 0; // 踩空了，说明这里没有节点，返回 0
    return 1 + countNodes(root->left) + countNodes(root->right);
}
```

### 2. 什么时候用 `if (!root->left && !root->right)` （叶子节点作为终点）？

**适用场景：所有带有“路径（Path）”字眼，或者只关注“树底端”的问题。**（比如：1022 题根到叶子的数字之和、988 题叶子到根的字符串、判断路径总和）。

- **物理意义**：你走到了死胡同，前面没有路了，但你现在实实在在地踩在一个节点上。
- **潜台词**：“这条路走到底了，赶紧把这一路上攒下来的业绩结算一下！”
- **为什么选它**：就像咱们前面分析 1022 题时说的，如果找“路径”，你碰到只有左孩子的节点，走到它那个空的右孩子去结算是不对的，因为它根本不是这条路的尽头！**只有叶子节点，才是真正的“断头路”，才是结算路径的唯一合法地点。**

### 3. 黄金组合：大人，我全都要！

在实际做路径相关的题目时（比如你刚做的 1022 和 988），我们通常会把这两个终点**组合起来用**。

C++

```
void dfs(TreeNode* root, int sum) {
    // 终点 1：防撞墙（安全检查）
    // 如果不写这个，一旦遇到只有单边孩子的节点，走到空的那边时下一行 root->val 就会直接报段错误（操作空指针）
    if (!root) return; 

    sum += root->val;

    // 终点 2：真正的业务结算点（叶子节点）
    if (!root->left && !root->right) {
        // 结算并上报
        ans += sum; 
        return; 
    }

    dfs(root->left, sum);
    dfs(root->right, sum);
}
```

**看懂这个逻辑了吗？**

- `if (!root)` 是**保镖**，负责防止程序崩溃。
- `if (!root->left && !root->right)` 是**会计**，负责在这条路走完时核对账目。

| **题目特征**                                  | **递归终点选谁？**                              | **举例**                               |
| --------------------------------------------- | ----------------------------------------------- | -------------------------------------- |
| **整体属性** (操作所有节点，不关心路在哪断的) | **空节点** `if (!root)`                         | 求最大深度、翻转二叉树、1315题偶数爷爷 |
| **路径问题** (找一条从头到尾的线)             | **叶子节点** `if (!root->left && !root->right)` | 1022题根到叶求和、打印所有路径         |
| **防空指针** (只要后续代码访问了 `root->val`) | **必须先写** `if (!root)` 打底                  | 几乎所有题的第一行                     |
